# Base 线稿画板

将需求里的关键状态画成飞书云文档内可编辑的画板。以当前需求、明确的评审结论和用户提供的最新界面为准。底稿是结构参考，底稿中的字段、按钮和状态不代表已经确认的产品行为。

## 1. 从需求取状态

读用户指定的段落，记下入口、操作者、原状态、操作、何时生效和可见结果。先选能走通的最少帧，再补会改变用户判断的异常或权限分支。把已确定和待定的规则分开。只有目标文档或关键交互存在多个合理解释且影响交付时才问用户，其他内容先准备。

为每帧记录标题、底稿 ID、需修改的 UI、前后状态和一句图外注释。方案对比共用同一底稿和示例数据。具体取舍见 [编帧与样式](references/storyboarding.md)。

## 2. 选底稿并改图

从 [底稿目录](assets/catalog.json) 按场景选取 SVG，PNG 可快速对照。桌面底稿覆盖数据表、看板、日历、甘特、画册、表单编辑与填写、仪表盘、问卷与关联结果表、工作流、高级权限，按真实参考的布局重绘；其他弹窗与手机模板为补充示意。表单和问卷、编辑态和填写态应分别选择。用副本修改字段、文案、控件及状态。缺少底稿时，沿用最接近的页面框架，补真实的控件位置。敏感页面用虚构记录重新画。没有参考截图时，用模板表达已确认的结构和动作，把无法验证的细节当作示意。

保留界面的导航、标题、视图栏和相邻操作，用一致的灰阶降低背景存在感。每帧用同一种强调色指出本步的入口或结果。说明、编号、箭头放在界面外。桌面帧优先横向串联，手机保留底部面板、键盘和安全区的实际占位。尽量用可编辑文字和独立图元。

背景文案按需简化：左侧用「数据表1」「数据表2」「收集表1」等通用名称；视图页签直接用「表格」「看板」「日历」「甘特图」「画册」「表单」；背景记录用「示例数据」、选项占位或短灰条，不完整复刻截图中的业务字段、名称和数据。只对本次需求涉及的字段、按钮、内容格式、状态和结果保留必要细节。布局贴合参考，信息量服务于需求重点。

有用户参考时，按 [参考图核对](references/source-fidelity.md) 检查整体比例、页面区域、内容密度和滚动位置。不要把真实页面改成泛化的应用布局，也不要为了演示入口把屏外控件移到可见区。视觉贴合与技术可编辑性分别验收；写入成功或原生节点检查通过，不能代替与参考图逐张对照。

可用 [拼版工具](scripts/compose.py) 组合单帧 SVG。用 [可编辑性检查](scripts/verify_native.py) 确认关键标题、字段、操作按钮是画板里的原生文字节点。完整示例见 [使用说明](README.md)。

## 3. 写入飞书画板并验收

按 [飞书画板交付](references/feishu-whiteboard.md) 操作。新图插入用户指定章节的画板，已有画板优先追加到空区或按稳定节点 ID 局部修改。优先使用已授权的飞书文档、画板连接；本地有 lark-cli 时可按参考中的已验证命令执行。调用者需要目标的编辑权限。

写前同时检查本地渲染和原生节点。写后读回目标画板和更新节点，确认标题、控件位置、前后状态、字号、截断和旁边原有内容。以最终画板为交付，PNG 仅供预览。访问或编辑权限不足时，交付可导入的 SVG 或原生节点文件，并准确说明线上状态。
