# 编帧与样式

## 把规则变成看得见的状态

| 需求 | 最少要画的变化 |
| --- | --- |
| 新增字段或切换字段类型 | 列头或已有字段入口、类型分组和选择态、字段配置、确认后的单元格。有损转换加确认和结果。各端各自核对入口。 |
| 富内容编辑 | 表格或卡片的摘要、记录详情完整展示、原地编辑与展开编辑。若保存方式不同，分别画出真实的按钮和生效时机。分享和权限影响阅读结果时，独立补一帧。 |
| Excel 追加导入 | 上传、字段匹配或人工映射、确认写入、导入结果。预览映射和实际新增记录需要有可辨认的区别。失败可重试时画重试范围。 |
| 表或视图描述 | 入口、没有描述、已有描述、编辑或清空。只读角色与保存失败会改变可用操作时才补帧。 |
| Base App、仪表盘、表单 | 明确内容在列表、卡片、详情、图表或表单的哪个位置。看板、日历、甘特、画册各沿用自己的字段展示位。结果或只读态与编辑态分开。 |

1. 每帧聚焦一个动作或结果。比如「打开字段选择」和「配置富文本字段」分别画，预览与写入成功也分别画。
2. 用同一小组占位字段和记录贯穿流程，背景导航每类通常 1–2 个、记录或卡片通常 2–3 条，用「示例数据」或短灰条表达，其余留白。只有解释本次需求的短值、长值、空值和内容格式时才展开具体示例；涉及批量或密集数据时再增加数量。使用真实的操作按钮文案，评审注释放在图外。
3. 同一流程保留稳定的窗口尺寸、视图布局和选中位置。两个方案放同级并排，只有行为不同时才改变画面。
4. 显示足够的上下文来定位操作。桌面保留导航、视图栏、工具栏和实际字段位置。移动端用触控尺寸、底部面板和键盘留白。无真实参考时，用模板的结构表达交互，像素和未确定文案按示意处理。

## 视觉和可编辑

- 结构用浅灰和白底，正文用足够对比度的深灰，重点用蓝色边框或浅蓝背景。错误或警示色只在有相应状态时使用。
- 标题、选项、按钮、字段名用独立 SVG 文字。轮廓、控件、连线用简单几何节点。按场景分组，保持合适的绘制顺序。避免将页面铺成单张截图。经授权使用局部截图时，也要保留前景控件、标注和关键文案的独立节点。
- 用画板实际渲染检查文字尺寸、换行、截断、箭头方向和弹窗遮挡。以单帧尺度检查读得清，再检查整体分组和排列。截图或源 SVG 看起来正确，不能代替飞书导入后的检查。
