# 参考界面与底稿核对

当用户提供截图时，以最新截图为页面结构依据。底稿帮助复用结构，不能用较通用的模板替换截图中的真实布局。结构贴合不要求业务文案逐项还原：导航用「数据表1」「收集表1」，视图用类型名称，背景记录用「示例数据」或短灰条。只展开与需求有关的信息，不复制个人身份、内部路径、水印或整套业务数据。

## 先核对结构，再核对可编辑性

这两项单独验收。节点能写入飞书、文字是原生节点，并不说明界面已经贴合参考。

视觉核对时把参考与生成预览同时打开，重点比较：

- 导航层级和比例：顶栏、左侧资源树、视图页签、工具栏与正文起点。
- 场景结构：看板的窄高列卡、日历整月网格、甘特的记录列与日刻度、画册的多列卡片。不要统一替换成通用卡片页面。
- 页面状态：表单编辑态有题型面板，填写态没有；问卷与问卷结果表有不同正文；高级权限是覆盖背景的多列弹窗。
- 页面密度和位置：保留表格贴边、行高、卡片列数、模态框尺寸、主要入口与相邻操作；背景文字可以减少，用留白或短灰条保留占位。
- 文字截断、遮挡及视口边界。方案对比要共用同一套背景和示例数据，仅改讨论中的差异。

无需逐像素临摹照片、装饰封面或完整业务数据。可以简化这些内容，但保留其实际占位；被需求修改的控件、状态和文字应明确展示。

## 技术核对

转换后检查关键字段、按钮和标签是独立原生文字；控件、线条也应保留可编辑图元。再写入隔离测试画板、回读原始结构并导出当前 SVG，确认线上与本地布局一致。缩略图可能滞后，不能只看写入成功回执或旧缩略图。

交付时分别说明哪些模板已完成视觉对照、哪些场景已线上验证。不要用少量场景的技术通过代表所有页面的视觉通过。
