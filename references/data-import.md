# Base 数据导入需求

用于设计和评审把表格文件或其他来源数据导入 Base 的需求。重点核对导入目标、字段对应、值的转换、写入结果与失败恢复。

## 确定任务和边界

1. 先确认业务结果。创建新表、向已有表按行追加、按业务键更新记录分别建模。让用户用一组输入和期望的目标表说明「汇总」的含义。
2. 列出本期来源、文件数、工作表数和入口。分别定义本地文件、来源工作表和目标数据表。支持多个工作表的文件与一次导入多个工作表是两个决策。
3. 核对现有能力和竞品。记录测到的产品、入口、测试输入和最后一个已验证状态。只走到上传框或预览时，把写入结果列为待核实。
4. 按影响收敛范围。先确定新增、更新、去重和风险确认，再确定控件形式与文案。文件大小、行数、编码等限制结合现有能力和研发评估确定。

## 把三类规则分别写清

| 规则 | 应回答的问题 | 产出 |
|---|---|---|
| 字段写入 | 给定来源值和目标字段，写入什么 | 可接受值、转换结果、异常处理 |
| 入口分流 | 哪些情况可直接导入，哪些需要人工确认 | 直接导入、预览确认、阻断的条件 |
| 预览初始态 | 打开预览后用户看到什么、能改什么 | 默认映射、勾选和禁用状态、风险提示 |

已有表导入以目标字段及其配置为准。将来源识别类型与目标类型分开，再判断具体值能否写入以及是否损失信息。新建导入会推断字段类型，可用作观察来源行为的依据。

逐字段定义接受值、转换结果、异常和边界。先写规则，再用独立示例说明。对数值区分来源实际值与显示值。对多选、日期、图片、链接等容易歧义的内容写清拆分、格式和保留范围。遇到只有实现摘要或没有权限核对源码的规则，记录观察事实、已确认决策和待核实项。

## 字段映射和分流

1. **确定本次范围。** 记录目标表、来源工作表、表头与有效数据行。预览、实际写入、失败恢复使用同一份配置。CSV 可复用后续映射，但需单独确认编码、分隔符和无工作表时的交互。
2. **计算唯一对应。** 将本次准备导入的来源列匹配到可写目标字段。明确名称比较方式、重复或空表头的处理、来源多列和目标缺列的结果。分别判断系统不可写、用户无写入权限和本期不支持三类状态。
3. **检查内容。** 匹配关系明确后，依据目标字段规则判断可写、可转换或有损。若以抽样检查代替全量判断，应把抽样范围、发现异常后的动作及剩余风险写清。
4. **选择路径。** 推荐把直接导入限定为范围明确、待导入来源有唯一去向、已确认无需处理可识别风险的情况。有歧义、可能丢失内容或需用户补充配置时进入预览。权限、容量或文件校验无法满足时提示原因并阻止对应操作。
5. **初始化预览。** 普通可写字段若有唯一同名来源，可预选并允许改选。无法确定对应关系的行等待用户选择。若索引字段必选，锁定目标的勾选状态，同时明确来源是否可替换。不可写索引字段显示原因，由系统按该字段规则产生结果。
6. **更新与确认。** 修改来源列、工作表、表头选项和拟新增字段后更新预览。定义切回工作表是否恢复草稿，以及恢复默认会复位哪些项目。提交前让用户清楚看到将写入的值和被跳过的内容，明确风险提示放在来源选择还是结果区。

预览是写入规则的样例。将同一来源值在直接导入和手动确认路径中的预期结果对照，避免两条路径使用不同的转换口径。

## 权限、失败与并发

- **权限。** 分开判断目标表新增记录、创建字段和字段写入权限。新建表和追加数据分别判定。明确入口、选项与最终执行各自的表现，提交时由服务端重新鉴权。
- **目标一致。** 确认时重新校验目标表、字段、权限和剩余容量。预览后有字段被删、改类型或失去权限时，明确刷新映射、阻断或按既定范围继续的条件。
- **阶段恢复。** 上传、解析、匹配、写入分别定义失败去向。重试可以恢复上一次交互与配置，或按明确规则自动重试。分别说明文件、工作表、映射、表头设置和拟新增字段如何保留。
- **写入失败分类。** 可修正的值错误应能定位并回到相应预览。确认未写入的执行失败按恢复规则重试。超时或断连使结果未知时，先按原任务查询或核对写入结果，再决定补写范围。
- **部分提交。** 写清字段创建成功但记录写入失败时的目标表状态。若支持部分成功，定义成功与失败的粒度、用户看到的结果，以及重试会尝试的范围。退出和恢复默认仅处理各自作用域的配置。
- **重复操作。** 区分用户再次主动导入同一份文件与同一次写入因超时被重试。确认幂等或冲突策略，给出重复点击、请求超时、同时写入和重试后的预期记录数。

## 合成验收用例

以下用例使用虚构字段和值。按当前需求确定各规则后再换成可执行的验收数据。

| 输入与操作 | 核对结果 |
|---|---|
| 文件列「标题」「备注」与目标唯一同名，值兼容且范围明确 | 命中直接路径，按有效行新增记录，旧记录保留 |
| 来源值实际为数字 `12`，目标为允许转换的文本字段 | 预览和最终均写入 `12`，来源类型差异不会单独触发风险 |
| 同名「日期」的来源值是「待定」 | 进入预览，显示已确认的损失提示，提交后按规则留空或阻断 |
| 两个来源列同名，另有带内容的来源列没有去向 | 不猜测映射，预览按规则提示，人工调整后才继续 |
| 可写索引字段没有同名列，另测索引字段为自动编号 | 可写时按约定给候选，目标勾选锁定，来源可换。自动编号场景显示禁用原因并按系统规则生成值 |
| 勾选跳过首行后取消勾选，切换工作表后再切回，最后恢复默认 | 首行在预览和写入范围中同步变化，切回及复位只影响约定的作用域 |
| 能创建数据表但不能向当前表新增记录，或确认前写入权限被撤销 | 新建与追加各自给出权限状态，服务端按最新权限拒绝不允许的写入 |
| 上传失败、解析失败、已预览后写入失败分别点击重试 | 恢复各自对应的交互和配置，按既定触发方式重新执行 |
| 一次导入已创建字段且部分写入，随后超时并触发重试 | 按已确认的部分提交策略保留或回滚，重试后目标字段和记录数量可预期 |
| 目标原有 2 行，新增 2 行已提交但回执丢失，随后对同一任务重试，再主动发起一次新导入 | 同一任务核对完成后仍为 4 行。若策略允许主动再次导入，新任务完成后为 6 行 |

## 追加导入案例示例

- **样例中已决。** 按行新增，每次一个文件，可连续追加。目标字段与值兼容且不存在需人工确认的风险时可直接导入。已有映射在预览中保留。失败重试恢复相应界面，由用户再次确认。已创建字段保留，确认退出后清空本次临时配置。
- **曾改。** 起始行从复选框改为第 N 行选择器，后续又确定为默认勾选的复选框。用户取消勾选时导入首行。上传过渡态留在上传弹窗内。字段风险提示由预览格内标记改为来源选择处统一提示，异常预览格留空。
- **待核实。** 文件与容量上限、字段接受的具体日期形式和多选分隔符、附件转换、部分写入后的重试幂等规则。起始行的中英文名称与提示文案另行确认。来源范围变化须带着入口、授权、解析和失败链路一起审查。

## 核对评审交付

把每条评审意见对应到现行正文、画板节点或待决策事项。未解决的评论可能已被新版本覆盖，图中状态也可能与正文不同。更新流程或控件后，回读正式版本并验证图文的触发条件、配置保留与成功结果。发布后分别核对正文内容、资源结构和用户实际看到的画面。流程图展示主要判断与去向，细节放在对应场景的规则和线稿中。
