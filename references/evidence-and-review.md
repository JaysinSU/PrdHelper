# 证据、评审与变更跟踪

用于核对现状、做竞品对比、评审需求、处理评论或追踪方案改动。

## 决策台账

| 分类 | 记录什么 | 怎样使用 |
| --- | --- | --- |
| 已确认 | 原话或决议、适用范围、时间、出处 | 作为当前规则。后续明确调整时记录被替换项 |
| 已观察 | 产品、版本或时间、角色、入口、实际完成的步骤和结果 | 支撑该场景下的行为。保留验证终点 |
| 参考 | 竞品、模板、旧方案或相似能力及其可借鉴点 | 作为设计依据，标出迁移成立的前提 |
| 建议 | 方案、取舍、预期收益及理由 | 写为建议或待评审方向 |
| 待定 | 冲突或缺失、影响、决策人和下一步 | 放在受影响规则旁，给可行动的问题 |

表格字段可用「问题｜当前决定或状态｜适用范围｜证据｜后续动作」。当正文、图、评论与实测互相矛盾时，检查是否在说同一个对象、版本、入口或端，再查最新的明确决议。材料仍冲突时，把各自口径和会改变的结果一起呈现。

## 找现状和竞品

1. 先写用户尝试完成的任务，以及现有路径多了哪一步或出现了什么错误。反馈保留时间、对象、上下文和可访问出处。表级痛点只支撑表级需求，视图级价值需有独立场景。
2. 用相同的比较维度检查产品。以导入为例，分别验证来源、目标、映射、确认、实际落库和恢复。在配置页看到选项只证明入口或配置可见。
3. 正文先总结各维度的共性、差异和对本期决策的影响。逐产品操作及截图作为查阅材料。对未能实测的路径写清终点和待查项。
4. 估算注明观察窗口、对象、分母、假设及去重方法。评审、排期和上线是不同状态，发布口径查发布证据。

## 审阅正文和评论

| 检查 | 输出 |
| --- | --- |
| 主路径的必要步骤能否走通 | 起始条件、关键动作、可见结果和落库条件 |
| 权限、部分成功、重试、数据丢失 | 最短反例、影响对象、规则候选及需确认的问题 |
| 同一口径在多处出现 | 正文条目、图中状态、矩阵、文案和用例的对应关系 |
| 未解决评论 | 逐条记录目前正文和图是否覆盖，区分已覆盖、部分覆盖、待决策、无法核实 |

优先交付会改变数据结果、权限或本期范围的发现。每条用「原位置 → 具体反例 → 影响 → 可执行修改」说明。评审授权可用于给出修改建议，按用户已授权的范围写入文档或操作评论。

## 把调整同步到下游

1. 读取最新正文、目标图及相关评论。用最小文本片段和稳定锚点定位。
2. 记录新规则及其取代的旧规则。同步受影响的入口、控件初始值、状态保留、失败恢复、端和分享、验收及文案。
3. 示例练习中，导入起始行从选行器改回表头勾选框。要一并核对 Sheet 切换时的独立状态、实时预览、恢复默认、失败后回到哪个状态和画板中的控件。
4. 对正文与画板分别回读。评论已关闭、锚点已迁移或缩略图暂未刷新都只说明该项现状，需结合现行内容判断覆盖情况。
