# Base 新字段与富文本

用于拆解 Base 的新字段、字段能力升级和跨入口适配。先写用户需要完成的业务，再选择相关规则与验收用例。以下富文本规则是合成示例，应用前以本需求已确认的决策为准。

## 值语义

- 先定义一个字段值承载什么，以及创建、清空、更新时如何判断值发生变化。分别确认用户看到的字段形态、类型枚举、存储结构与对外读写契约。
- 用内容清单明确文字、段落、链接、图片等元素的录入、显示和保存范围。对同一内容分别定义完整值、纯文本结果和界面摘要的生成规则。
- 定义未赋值、显式清空、无有效内容及内容暂不可见。确认默认值应用时机，以及索引列的使用资格和标题提取规则。
- 为搜索、筛选、排序、分组、公式、查找引用和事件触发指定使用的值。明确仅样式、勾选状态或图片引用改变时，是否更新历史和触发流程。

| 表达 | 需要定义 | 富文本示例 |
|---|---|---|
| 完整值 | 支持元素、顺序、样式和资源引用 | 保存正文、列表结构、勾选状态、图片与链接 |
| 纯文本结果 | 提取顺序、换行、链接名称、列表标记 | 公式读可见文字，图片中的文字不参与提取 |
| 界面摘要 | 提取来源、截断规则和展开入口 | 卡片按纯文字摘要展示，打开记录详情看完整内容 |
| 有效值 | 空白、结构占位和媒体是否算已填写 | 成功保存的仅图值算已填，即使文字摘要为空 |

## 转换矩阵

按「来源类型 × 目标类型 × 操作路径」拆分。分别定义列转、复制粘贴、导入导出、同步及 API 写回。相同来源和目标走不同路径时，可以有不同规则。

| 路径 | 来源 → 目标 | 富文本示例 | 要确认的行为 |
|---|---|---|---|
| 列转 | 文本 → 富文本 | 按约定识别支持的 Markdown 语法，其他字符按原文保留 | 解析范围、受影响记录和执行前提示 |
| 列转 | 富文本 → 文本 | 保留可读文字，处理列表、链接和图片的表达差异 | 仅图值如何处理，转换后能否恢复 |
| 粘贴 | 外部文本 → 富文本 | 普通粘贴保留 Markdown 字符 | 是否有单独的粘贴为纯文本或按格式导入入口 |
| 复制或直接赋值 | 富文本 → 富文本 | 在目标允许的范围内保留结构与图片 | 资源权限、图片重新关联和不兼容时的结果 |
| 导入或 API 写入 | 外部文本或结构化内容 → 富文本 | 文本按文本契约写入，完整内容按声明的格式写入 | 结构版本、旧调用方、有损写入的处理 |

- 每行列出可保留元素、降级结果、无法转换的处理、界面提示或调用错误，以及最终值。提供一条有损样例，明确哪些情形允许置空、跳过或拒绝。
- 批量列转补充确认时机、转换期间可执行的操作、部分失败后的字段类型和记录值，以及重试与恢复规则。对复制、公式等消费方受影响的范围单独说明。

## 展示与编辑点位

按「入口 × 角色权限 × 客户端」填写矩阵。展示、完整阅读、编辑与字段配置分别定义。分享和嵌入场景引用对应点位的显示规则，再说明权限差异。

| 点位 | 展示 | 阅读或编辑 |
|---|---|---|
| 表格视图单元格 | 示例中保留基础格式，按行高截断，图片可显示缩略信息 | 从单元格展开阅读或进入编辑，按权限开放 |
| 看板、画册 | 示例中在卡片的字段区展示多行纯文字摘要 | 打开记录详情阅读或编辑完整内容 |
| 日历、甘特 | 示例中日历在日程预览浮窗展示摘要，甘特左侧列用单行摘要。日程块与时间条沿用记录标题规则 | 从各自入口打开记录详情 |
| 记录详情、记录分享页 | 按各自授权呈现完整内容 | 区分可读、可编辑、可预览图片和可复制 |
| 视图分享页、仪表盘、应用组件 | 标明继承哪种视图规则，或单列组件行为 | 写清可展开的入口与支持编辑的位置 |
| 表单、问卷 | 区分配置预览、填写、查询与提交结果 | 分开定义字段草稿、表单提交和结果修改 |

- PC、移动端、Pad 和 H5 按实际交付范围核对配置、录入、完整阅读、保存失败和旧端处理。只读态沿用所在点位的显示规则，并限制会改变值的操作。
- 校对全局用语的适用范围。例如把「单元格展示引用样式」限定到支持格式的表格视图。以只读记录详情为例写出的图片预览规则，也要标明适用入口。

## 资源、失败与兼容

- 分别定义记录、字段和资源的查看与编辑权限，以及复制、下载、导出的权限。跳转到链接或提及对象时按目标权限判断。匿名表单上传资源与读取底表分别授权。
- 区分新图片正在上传或上传失败、已保存图片暂时加载失败、资源已失效和当前用户无权限。明确各状态的占位、重试、保留引用和保存规则。
- 定义草稿提交时机、失败后的内容去向、关闭或刷新后的恢复能力、多人编辑的冲突范围和恢复入口。旧值、草稿、未提交图片和正式写入分别处理。
- 核对新旧客户端与接口的读取和写回。旧端可按已定策略读摘要或提示升级，写入要防止不兼容的全文覆盖。验证编辑同一记录的其他字段时仍能保留原值。
- 对图片说明上传、复制、跨表引用、历史恢复与清理。若允许合法副本独立访问，验证来源记录变化后目标仍可读取，并按目标权限访问。
- 灰度分别定义新增或转换入口、已创建字段的可读与可写，以及旧端保护和回滚。容量和性能参数如需研发评估，先确定用户可见的超限与失败行为。

## 合成验收用例

将用例中的示例策略换成本需求已确认的规则，再补入实际入口和权限角色。

1. 同一段 `# 标题` 分别走列转与普通粘贴。列转按示例识别已支持语法，粘贴保留原文字。未支持语法按已确认策略处理。
2. 含链接和仅含图片的记录转为文本。确认前能看到相应损失提示，确认后核对链接文字和地址是否保留，以及仅图值是否按约定置空或拒绝转换。取消后原值保留。
3. 保存仅含成功上传图片的值。按示例，必填可通过，「不为空」能命中，纯文字摘要为空，记录详情可预览图片。
4. 在表格、看板、画册、日历、甘特与详情打开同一记录。逐一核对承载位置、截断和阅读入口。日程块及时间条取记录标题。
5. 只读用户查看卡片及其记录详情。卡片显示约定的摘要，详情按权限显示完整值，尝试编辑或勾选正文任务项时原值不变。
6. 旧图片暂时加载失败时修改正文，再添加一张上传失败的新图。逐项验证既有引用与本次新增资源的保存规则、提示及重试路径。
7. 两人编辑同一值，其中一人先保存。验证冲突处理和另一份修改的恢复方式。另测同记录其他字段变化时，冲突范围符合约定。
8. 表单确认单题后提交整表单，并模拟提交失败。验证题目草稿与正式记录的提交时机，检查重试结果及匿名填写者的资源访问范围。
9. 旧客户端或旧 API 读到纯文本后写回。验证约定的结果及反馈。再只更新同记录的其他字段，检查正文结构与图片引用仍可完整读取。
