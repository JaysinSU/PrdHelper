# 对象说明与附属元数据

适用于为数据表、视图、字段等对象增加描述、使用说明、标签或其他附属元数据。开始前先确认谁维护、谁消费、何时需要、内容跟随哪个对象。若诉求是变更通知或确认已读，单独评估触达和回执链路。

## 明确对象归属与生命周期

- 用一个业务场景解释新增内容的作用和现有替代方案的成本。每个对象层级分别举证。例如表说明解释整表用途，视图说明解释当前筛选口径，字段说明解释值的填写方式。
- 写清内容跟随哪个对象，是否独立维护、继承或覆盖。若依赖筛选条件、字段或模板，定义依赖变化后是否自动更新、标记过时或由维护者修订。
- 分开定义值为空、清空并保存、纯空白、只有链接或媒体的行为。明确何时显示入口、必填如何判断，以及清除是否可撤销。
- 区分元数据权限、对象结构权限和对象内容权限。覆盖能改记录但不能改对象配置、能维护数据表但不能维护受保护视图等组合。

| 生命周期 | 要写清的规则 |
| --- | --- |
| 新建、重命名、调整顺序 | 初始值、元数据是否随原对象保留、入口何时显示 |
| 复制配置、复制完整对象 | 是否携带元数据、子对象说明及资源，复制后是否独立维护 |
| 跨空间复制、迁移、模板实例化 | 内容与资源的授权归属，来源被删除或撤权后如何阅读 |
| 删除、归档、恢复 | 说明的可见性，恢复时能取到哪一版内容，历史资源是否仍可读取 |
| 关联、同步、导出 | 各渠道的可见、可编辑和格式保留规则，权限校验时机 |

## 建立入口、端和角色矩阵

每行写一个用户实际可达的点位。角色列填写可读、可编辑、只读或不可见，并明确菜单、图标和快捷键的表现。存在多层授权时写判定条件及优先级。

| 点位 | 端或容器 | 可维护者 | 仅可读者 | 无访问权者 |
| --- | --- | --- | --- | --- |
| 对象名称旁的说明入口 | PC 主页面 | 写清阅读动作与进入编辑的动作 | 写清阅读方式与点击反应 | 写清入口与内容是否可见 |
| 对象更多菜单 | PC、移动端或 Pad | 写清新增与修改入口 | 明确置灰、隐藏或其他表现 | 沿用已核实的对象权限规则 |
| 导航、详情或底部浮层 | 移动端、Pad | 明确本期能做的操作 | 写清展开、滚动及关闭后返回位置 | 写清页面或对象的缺省态 |
| 分享、嵌入或外部页面 | Web、H5 或嵌入容器 | 按实际授权定义读写 | 定义正文、链接和资源的可读范围 | 按现有鉴权显示访问结果 |

- 分享页、旧端和功能灰度分别列行。区分能看到入口、能阅读存量、能创建或写入。验证未命中灰度的人打开已配置对象时，读取和保存是否符合预期。
- 写清悬停、点击、触屏与键盘的等效路径。点开说明时，明确是否同时触发切表、切视图或打开详情。
- 用现有产品界面验证复用点。截图显示入口只能证明入口存在。涉及保存、权限与不同端时，分别验证该行为或标为待核实。

## 写成可执行的编辑状态

每种状态同时说明编辑框、已保存值、草稿、可用动作和下一步。区分即时保存、明确提交和随父表单提交，按业务风险选择。

| 状态或动作 | 要写清的规则 |
| --- | --- |
| 首次进入、读取失败 | 展示空态或已保存内容。读取失败如何重试，防止空编辑框误覆盖旧值 |
| 未改动、改动后恢复原值 | 定义内容相等的口径及是否进入未改动态，说明关闭与背景操作是否生效 |
| 已改动、取消或离开 | 定义关闭按钮、背景点击、返回键和 Esc 的效果，明确保留或丢弃草稿的条件 |
| 内容超限或不合法 | 定义客户端提示、服务端校验和按钮状态。区分显示截断与数据裁剪，提供完整阅读路径 |
| 提交中、保存成功 | 指定何时结束编辑、何时更新阅读入口和已保存值，明确重复提交如何处理 |
| 保存失败、断网或请求超时 | 保留可继续编辑的输入，明确从哪里恢复和重试。区分确认失败与结果未知，避免重复写入 |
| 并发或编辑中失去权限 | 保存时重校权限与版本，定义新旧内容的展示、恢复与允许的后续动作 |
| 清空并保存 | 区分删除已保存说明和清空输入草稿，定义成功后入口与历史的表现 |

把失败后用户如何找回内容写进验收。研发评估缓存位置、保存期限与跨端恢复的可行性，设计确定控件尺寸与布局。若提交后立即关闭编辑框，评审时给出失败后重新进入的具体路径。

## 合成验收用例

以下示例假定表与视图说明独立维护，PC 支持编辑，移动端和分享页只读，完整复制携带说明，保存成功后更新已保存值。替换为实际项目已确认的规则后再验收。

| 场景 | 操作与预期 |
| --- | --- |
| 独立维护 | 同一张表写入用途说明，其视图另写筛选口径。修改表说明，视图仍展示自己的口径 |
| 权限与保护 | 可读但不可维护的成员能阅读。编辑入口符合约定。维护者也无法修改受保护视图，仍可在有权限时编辑表说明 |
| 无改动关闭 | 打开编辑框后直接点击另一张表。按约定只关闭编辑框，当前表保持原位 |
| 已改动退出 | 输入新文字后点击背景。编辑框和输入保留。明确放弃后再打开，恢复最近一次成功保存的值 |
| 超限与长文阅读 | 输入超过约定上限，保存被禁用。删回有效范围后可以保存，阅读时可滚动查看末尾并打开链接 |
| 保存失败重试 | 修改说明后模拟断网。旧说明仍可读，用户从约定入口找回本次输入。恢复网络后重试，只生成一次成功变更 |
| 并发与权限变化 | 两人打开同一对象。一方先保存或另一方被撤去维护权限时，后提交者收到相应提示，较新内容不会被静默覆盖 |
| 复制、清空与恢复 | 复制完整对象后修改副本说明，原对象的说明不变。清空副本并保存后入口按约定隐藏，历史恢复结果符合产品规则 |
| 移动端与分享 | 在移动端导航展开说明并关闭，回到原导航位置。分享访客只能读取获准内容，撤回访问权后资源也无法读取 |

## 历史案例如何复用

- 某次表与视图描述需求从公告诉求收敛为按需查看说明。表与视图分别维护，既有字段说明作为交互参考。可复用的是对象分层、就地阅读和按权限编辑的判断方式。
- 该案例选择 PC 编辑、移动端阅读、分享只读，清空保存后移除说明图标，表与视图副本携带描述。长度上限、空白值规则、菜单样式、保存后何时关闭和失败草稿策略均需按当前场景确定。
- 区分用户明确确认的规则、历史方案建议和待评估项。历史快照只用来定位值得验证的规则，现状与发布范围以当前产品、设计和评审结论为准。
- 价值度量至少区分成功配置、实际落库和协作者阅读。覆盖率优先使用服务端存量数据，保存成功率以落库结果计，阅读口径以正文展示计。
