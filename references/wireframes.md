# 流程、线稿与画板

用于解释产品对象、分支路径、实际入口和关键状态。流程回答动作顺序与生效点，线稿回答控件位置、当下能做什么和反馈长什么样。

## 编帧

1. 从主任务挑选足以走通的帧，按用户操作顺序排列。每帧保留真实的页面层级、相邻入口和组件。用虚构记录、简化字段和淡化背景聚焦变更。
2. 对会改变数据或权限的分支补帧。常见分支包括空内容、无权限、可恢复错误、有损确认和保存成功。若两个状态的可见结果相同，可用注释合并。
3. 用同一组输入贯穿前后帧。标明确认前、预览、提交中和已完成。若预览和实际写入规则不同，分别给可观察结果。
4. 保持同类画面比例和顺序一致。较宽的桌面场景可横向排布，移动端用真实容器。文字和按钮保留可读大小。

| 示例 | 值得画的差异 |
| --- | --- |
| 追加导入 | 明确可直接导入、需选择映射的预览、权限受限、阶段失败与重试恢复 |
| 表与视图描述 | 空内容、存在说明、角色只能读、修改中、清空保存和失败反馈 |
| 富文本 | 写入前后、仅显示摘要的视图、完整记录详情、有损转换确认和分享只读 |

使用规范编号连接正文规则和关键状态。编号可用于审阅定位，用户界面中的标题、按钮和提示保持产品原样。检查视图内标题与正文是否混用，卡片和浮窗是否跟随已有展示规则。

## 更新既有画板

- 确认目标画板、文档位置、旧内容以及可放置的新区域。新增场景优先追加到不重叠的位置。替换时记录要移除的对象及其关联。
- 先检查预览的布局、字体、指向、截断、滚动和空态。写入前检查当前画板是否又有修改，按实际工具能力决定追加、局部替换或给待导入源文件。
- 写入回执只证明请求的处理结果。云端回读检查节点、位置和原有关联，实际导出或渲染确认可见结果。缩略图滞后时比对原始节点与当前导出，避免因缓存重复提交。
- 若容量、权限或格式导致部分成功，先定位已写入节点并核对能否安全修复。交付时给当前画板链接、可用预览和必要的可编辑源文件，标明各自验证范围。
